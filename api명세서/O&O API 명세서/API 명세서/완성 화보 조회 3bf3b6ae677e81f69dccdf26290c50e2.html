박제

mood · stats · muse_no는 mood_payload에 박제된 값을 그대로 낸다. 재계산하지 않는다.

무드 산출식을 나중에 튜닝하면 같은 방문도 다른 무드가 나온다. 공유된 링크를 나중에 열었을 때 내용이 바뀌면 안 된다. reports.payload를 박제하는 것과 같은 이유다.

이미지는 이 응답을 지나가지 않는다

URL 문자열만 넘기고 브라우저가 CDN에서 직접 받는다. 올릴 때와 마찬가지로 내려받을 때도 서버를 우회한다.

stats를 배열로 둔 이유

P03 하단 지표는 기획에서 바뀔 가능성이 높다. 고정 필드로 박으면 항목 하나 추가할 때 API를 고쳐야 한다. label까지 서버가 내려주면 프론트는 순회만 하면 된다.

P04 공유

Figma P04는 버튼 3개다.

[인스타그램 스토리로 공유]  [이미지 저장]  [처음 화면으로]
웹에서 인스타그램 피드·스토리에 직접 올리는 공식 방법은 없다. navigator.share({files})로 OS 공유 시트를 띄우면 사용자가 거기서 인스타그램을 고르는 방식이 최선이다. 버튼 문구도 그에 맞춰 두는 게 정확하다.
iOS Safari는 download 속성을 무시한다. 이미지 저장도 navigator.share({files})를 먼저 시도하고, 안 되면 "길게 눌러 저장" 안내로 떨어뜨려야 한다.
버킷 CORS에 GET이 열려 있어야 한다. 이미지를 blob으로 받아야 navigator.share에 파일로 넘길 수 있다. <img src>로 보여주기만 할 때는 필요 없지만 파일로 다룰 때는 필요하다.

OG 태그 SSR은 이번 스코프에서 제외된다. 링크가 아니라 이미지 파일 자체를 공유하는 구조라 크롤러가 읽을 일이 없다.
