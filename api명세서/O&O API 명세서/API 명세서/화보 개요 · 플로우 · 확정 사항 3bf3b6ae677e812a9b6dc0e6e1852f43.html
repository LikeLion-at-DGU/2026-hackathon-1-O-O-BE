이게 뭐하는 기능인지

관람을 마치고 리포트를 본 사용자가 상품 하나를 고르고 → 사진을 찍고 → 자기만의 화보를 받아 인스타그램에 공유한다. 관람 데이터가 리포트에서 끝나지 않고 들고 나갈 결과물로 이어지는 구간이다.

무드는 P02에서 새로 계산하지 않는다. GET /reports/{slug} 응답에 이미 실려 있다.

왜 이렇게 나눴나

계산 API와 생성 API를 갈랐다. 후보 추천(P01)은 이미 있는 events와 reports.payload만으로 끝나고, 워커·스토리지·이미지 생성 API가 하나도 필요 없다. 반면 화보 생성은 25초짜리 외부 호출이다.

덕분에 가장 불확실한 이미지 생성을 맨 뒤로 미룰 수 있다. 벤더가 안 정해져도 P01~P03 프레임까지는 만들 수 있다.

생성은 반드시 워커로 보낸다. 15~40초 걸리는 호출을 뷰에 두면 uvicorn --workers 2에서 동시 2명에 서비스가 멈춘다. /finish에서 이미 검증된 패턴을 그대로 쓴다.
