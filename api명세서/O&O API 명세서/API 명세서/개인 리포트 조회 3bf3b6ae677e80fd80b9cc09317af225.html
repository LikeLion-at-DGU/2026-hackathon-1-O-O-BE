매장을 떠난 뒤 집에서도 열려야 하므로 slug가 곧 열쇠다.

설명

POST /finish가 발급한 slug로 박제된 리포트를 연다. 재계산하지 않는다. 몇 번을 열든 같은 화면이 나오고, 추천 로직을 나중에 고쳐도 이미 공유된 링크의 내용은 그대로다.

분석이 아직 안 끝났으면 status만 내려간다. 클라이언트는 잠시 뒤 다시 요청한다(폴링).

Request

인증 헤더가 필요 없다. Path 파라미터 slug 하나.

GET /api/v1/reports/r_7Ka9xQ

status 분기 — 프론트가 화면을 고른다

status화면
pending로딩. 잠시 뒤 다시 요청
ready리포트 본문
failed재시도 안내. 무한 pending을 피하려고 추가한 상태다

데이터가 거의 없는 방문 — is_exploring

입장만 하고 바로 나간 사람도 빈 화면을 보지 않는다. 개인 취향 점수가 0이어도 인기·신상품 점수로 추천이 채워지고, 캐릭터는 결정론적으로 CNPD가 나온다.

프론트는 is_exploring 하나로 분기한다. confidence 숫자를 직접 비교하지 말 것 — 기준값(0.35)이 바뀌면 서버만 고치면 되게 한다.

값화면
is_exploring: true"아직 탐색 중" 배지. 캐릭터는 참고용으로 약하게. 추천은 그대로 노출
is_exploring: false정상 리포트

왜 인증이 없나

집에서 열 때는 visit_token이 없다. 그래서 slug를 추측하기 어렵게 발급하고(secrets.token_urlsafe), 응답에 개인 식별 정보를 담지 않는다.

대신 X-Robots-Tag: noindex 를 붙인다. 무인증 공개라 검색엔진에 개인 리포트가 걸리면 사고이고, 이 헤더가 유일한 방어선이다.

상품 정보가 payload 안에 박제되어 있다

hero·recommendations·interested 항목에 name·thumbnail·price·external_url이 복사되어 들어 있다. 집에서는 토큰이 없어 GET /products/{id}를 부를 수 없기 때문이다.

나중에 상품 가격이 바뀌어도 이미 만들어진 리포트는 그대로다. 이게 의도된 동작이다.
