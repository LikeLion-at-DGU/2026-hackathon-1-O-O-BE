설명

메인 화면의 입장 버튼을 누를 때 호출한다. 서버는 익명 UUID를 확인하고(없으면 새로 발급), 이번 방문(Visit) 을 만든 뒤, 전시존(매대)과 상품 목록을 내려준다. 로그인은 없다.

매장은 하나로 고정이라 매장을 지정하는 파라미터는 받지 않는다. 서버가 기본 매장을 붙인다.

연령대·성별은 입장할 때 받는다. 기획상 리포트 직전이 아니라 초기에 받기로 확정했다. 분석 시작 시점부터 코호트 분류에 쓸 수 있고, 관람이 끝난 뒤 입력을 요구하지 않아 이탈이 줄어든다.

맵은 프론트가 직접 만든다. 이 응답의 scenes는 좌표·도면이 아니라 "어느 전시존에 어떤 상품이 속하는지"만 알려주는 논리적 구성이다.

Request

헤더: X-Anonymous-UUID ❌ (있으면 보내고, 없으면 서버가 새로 발급)

필드타입필수설명
age_bandstring❌연령대. 10s, 20s, 30s, 40s, 50s+
genderstring❌성별. female, male, other, na

건너뛰기를 허용하므로 둘 다 선택이다. 안 받아도 입장은 정상 처리된다.

{ "age_band": "20s", "gender": "female" }

Response 200

필드타입설명
anonymous_uuidstring신규 발급될 때만 포함. 클라이언트가 저장해둔다
visit_idstring이번 방문 식별자
visit_tokenstring이후 API 호출 시 헤더에 넣을 토큰
storeobject매장 기본 정보(고정 매장)
scenesarray전시존 목록 + 각 존에 속한 상품(간략 정보)
{
  "anonymous_uuid": "a1b2c3d4-...",
  "visit_id": "v_9f8e...",
  "visit_token": "eyJhbGci...",
  "store": { "store_id": "s_mcm", "name": "MCM 스토어" },
  "scenes": [
    { "scene_id": "sc_01", "no": 1, "name": "F/W 신상",
      "products": [ { "product_id": "p_101", "no": 1, "name": "Heritage 백팩", "thumbnail": "...", "price": 890000 } ] }
  ]
}
scenes와 상품에 no(번호)를 함께 준다. 챗봇이 "1번 진열대 3번 상품"처럼 번호로 안내할 수 있어야 하기 때문이다.

에러 / 관련 테이블

401(토큰 만료) · 500 INTERNAL_ERROR → users, visits, stores, products
