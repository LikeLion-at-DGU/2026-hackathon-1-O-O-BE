한 번의 호출로 사진과 마스크 두 개의 업로드 URL을 받는다.

왜 presign인가

사진을 Django 서버로 받으면 워커 프로세스가 업로드 시간 내내 묶인다. 매장 와이파이에서 500KB 올리는 데 3초씩 걸리면 동시 접속자만큼 프로세스가 물린다.

서버는 URL만 발급하고 파일은 브라우저에서 스토리지로 직행한다. 사진 바이트는 Django를 지나가지 않는다.

Request

{ "content_type": "image/jpeg", "byte_size": 412000 }

Response 200

{
  "photo_key": "photos/2026/08/17/9c1f4a2b.jpg",
  "photo_upload_url": "https://...",
  "mask_key": "photos/2026/08/17/9c1f4a2b_mask.png",
  "mask_upload_url": "https://...",
  "headers": {
    "photo": { "Content-Type": "image/jpeg" },
    "mask": { "Content-Type": "image/png" }
  },
  "expires_in": 600
}

프론트는 두 URL에 각각 PUT한 뒤 photo_key와 mask_key를 생성 요청에 넘긴다.

검증

항목값
content_typeimage/jpeg, image/png, image/webp
byte_size5MB 이하
photo_key는 서버가 만든다. 클라이언트 파일명을 쓰면 경로 조작(../../)과 한글·이모지 파일명이 그대로 들어온다. UUID로 덮으면 그 문제가 통째로 사라지고 키를 추측할 수 없게 되는 효과도 같이 온다.

마스크는 뭔가

인물 실루엣이다. 화보 생성 시 이 영역을 건드리지 않게 해서 체형과 얼굴을 보존한다.

프론트에서 MediaPipe Selfie Segmentation으로 만든다. 얼굴 검출과 같은 패키지라 추가 용량이 250KB 정도다.

촬영 직후 브라우저에서
 ├─ Face Detection      → photo_meta (구도 후보 필터)
 └─ Selfie Segmentation → mask PNG   (체형 보존)

마스크가 없어도 생성은 되지만 체형 일관성이 떨어진다.

버킷 설정

photos/      비공개. 워커만 접근. Lifecycle 24시간 만료
lookbooks/   공개 CDN. 완성된 화보
products/cutout/  배경 제거 상품 PNG
⚠️ 버킷 CORS를 반드시 열어야 한다. React가 별도 도메인이라 PUT이 cross-origin이다. GET도 열어야 P04에서 이미지를 blob으로 받아 공유·저장할 수 있다. 로컬은 same-origin이라 안 걸리고 배포하고 나서야 터지는 유형이다.
⚠️ photos/ Lifecycle 24시간을 배치로 대체하지 말 것. presign만 받고 안 올렸거나 사진만 올리고 이탈한 경우는 DB에 행이 없어서 배치가 못 찾는다. 파일 나이만 보는 Lifecycle이라야 정리된다. 얼굴 사진이라 누락되면 안 된다.
