기본 규칙

항목내용
Base URLhttps://api.oando.example/api/v1 (예시)
포맷요청·응답 모두 application/json, UTF-8
인증사용자 API는 로그인 없음. anonymous_uuid • visit_token 헤더 사용. /admin/*만 Bearer 인증
visit_token불투명 랜덤 문자열(JWT 아님). 토큰 안에 정보를 담지 않고 DB 행을 가리키기만 한다. 만료 조건은 두 개뿐 — ① /finish 호출(= exited_at 기록) 즉시, ② 진입 후 3시간 경과. 인증 시점에 즉시 판정하므로 배치를 기다리지 않는다
매장매장은 하나로 고정. 매장 지정 파라미터를 받지 않고 서버가 기본 매장을 붙인다
Stateless서버 메모리에 세션·대화 상태를 두지 않고 매 요청 DB에서 조회
멱등성/events는 event_id, /finish는 visit_id 기준으로 중복 요청 무시 (같은 결과 반환)
시간client_timestamp(클라 발생) + server_received_at(서버 수신) 둘 다 저장. ISO 8601 / UTC

운영 원칙

  • 원본 이벤트는 수정하지 않고(append-only), 분석 파생 데이터는 별도로 생성한다. 추천 로직을 바꿔도 원본으로 재분석할 수 있다.
  • 워커는 재시도·지수 백오프·멱등 처리·실패 보관(DLQ)으로 유실과 중복 집계를 방지한다.
  • 모든 추천·유형·리포트 결과에 근거와 confidence를 함께 제공한다.
  • 개인정보는 최소로 수집한다(기본값 익명 UUID). chat_logs는 마스킹·보존기간을 적용한다. 마스킹은 저장 직전에 하며, role=user(직접 타이핑)에만 적용한다. 나머지 role은 서버가 만든 문구라 개인정보가 들어갈 수 없다.
  • 세션 만료는 3시간. 뒤로가기·창 닫기는 종료가 아니며, 3시간 이내 재진입하면 같은 방문으로 이어진다(is_resumed: true). 3시간을 넘기면 새 방문이 생기지만 anonymous_uuid는 그대로라 같은 사람으로 인식된다(is_new: false).
  • 왜 24시간이 아니라 3시간인가 — 재방문은 이번 스코프가 아니고, 복구해야 할 건 뒤로가기·화면 잠금 같은 분 단위 이탈이다. 24시간으로 두면 어제 온 사람이 오늘 QR을 찍을 때 어제 방문에 이어붙어 체류시간이 20시간으로 집계된다. 3시간이면 관람(보통 20분~1시간)을 충분히 덤으면서 다음날 이어붙기를 막는다.
  • 미종료 방문은 야간 배치가 ended_at을 채워 정리하되 리포트는 만들지 않는다(is_auto_closed=true). 평균 체류시간 집계에서 제외한다. 배치는 만료 조건이 아니라 정리 작업이다 — 사용자 입장에선 배치가 늦게 돌아도 정확히 3시간이다.
  • age_band/gender는 users가 아니라 visits에 저장한다. 같은 사람이 다음 방문에서 다르게 답할 수 있고, 코호트 집계가 방문 단위이기 때문이다. users에 두면 마지막 입력이 과거 방문 집계까지 소급해 바꾼다.
