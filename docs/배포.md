## 1. 서버 생성 시 고를 값

| 항목 | 값 | 이유 |
| --- | --- | --- |
| OS | **Ubuntu 22.04** | Rocky도 되지만 Docker 자료가 Ubuntu 기준이 훨씬 많다 |
| 서버 타입 | High CPU 2vCore / 4GB / 무료 트래픽 1TB | **제공 사양 초과 시 과금** |
| 스토리지 | **루트 100GB 단일** | 50+50으로 나누면 데이터 스토리지를 직접 마운트·관리해야 한다 |
| 로그인 방식 | **비밀번호 방식** | 매뉴얼상 **브라우저 터미널은 SSH 키페어로 접속 불가**다. 키페어를 고르면 관리자 비밀번호를 따로 발급받아야 한다 |
| 공인 IP | 1개 | 지원 범위 |

생성 순서는 VPC → 서브넷 → 공인 IP → 서버다. root 비밀번호는 "[가비아 클라우드] 서버가 생성되었습니다" 메일에 있다.

> 터미널 창을 닫아도 세션은 살아 있다. 작업 후 반드시 `exit`.
> `Ctrl+Alt+Del`은 로그아웃이 아니라 **재부팅**이다.

## 2. 보안그룹 (보안 → 보안그룹)

| 포트 | 소스 | 용도 |
| --- | --- | --- |
| 443 | 0.0.0.0/0 | HTTPS |
| 80 | 0.0.0.0/0 | 인증서 발급 + HTTPS 리다이렉트 |
| 22 | **내 IP만** (또는 닫기) | 브라우저 터미널이 있어 없어도 작업 가능 |

**5432 · 6379는 열지 않는다.** 컨테이너끼리는 내부 네트워크로 통신한다. root 비밀번호 로그인이라 22를 전체 공개하면 브루트포스가 바로 들어온다.

## 3. 서버 초기 세팅

```bash

```

## 4. 구성

```
가비아 VM (2vCore / 4GB / 100GB)
└── docker compose
    ├── caddy      443 → 자동 HTTPS (Let's Encrypt), SSE 버퍼링 해제
    ├── web        uvicorn config.asgi --workers 2
    ├── postgres   SQLite 대체
    └── redis      화보 폴링 상태 (+ 나중에 Celery 브로커)
```

**web을 uvicorn(ASGI)으로 띄우는 이유** — 챗봇이 SSE 스트리밍이다. gunicorn(WSGI)이면 청크가 버퍼링되어 응답이 한 번에 나간다. 로컬 `runserver`에서는 되고 배포에서만 깨지는 대표 사례다.

## 5. .env 작성

`.env.example`을 복사해 채운다. 배포에서 **반드시** 바뀌는 값:

```bash
DEBUG=False
ALLOWED_HOSTS=api.example.com
CORS_ALLOWED_ORIGINS=https://프론트도메인
DJANGO_SECRET_KEY=<python -c "import secrets;print(secrets.token_urlsafe(50))">

DATABASE_URL=postgres://oando:비밀번호@postgres:5432/oando
REDIS_URL=redis://redis:6379/0

DOMAIN=api.example.com
POSTGRES_DB=oando
POSTGRES_USER=oando
POSTGRES_PASSWORD=<위와 같은 비밀번호>
```

> **`REDIS_URL`을 비우면 화보 폴링이 404가 난다.** LocMem 캐시는 프로세스마다 따로 놀아서 `--workers 2`에서 폴링이 다른 프로세스에 붙기 때문이다.

## 6. 기동

```bash
docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml run --rm web python manage.py migrate
docker compose -f docker-compose.prod.yml run --rm web python manage.py seed_demo
docker compose -f docker-compose.prod.yml run --rm web python manage.py seed_characters
docker compose -f docker-compose.prod.yml run --rm web python manage.py createsuperuser
```

마이그레이션은 web을 띄운 **뒤에 별도로** 돌린다. 여러 컨테이너가 동시에 마이그레이션하면 충돌한다.

## 7. HTTPS · 도메인

Let's Encrypt는 **IP로 인증서를 발급하지 않는다.** 그런데 HTTPS는 선택이 아니다.

- 프론트가 Vercel(HTTPS)이면 HTTP API 호출은 **mixed content로 차단**된다
- 화보 공유(`navigator.share`)는 secure context에서만 동작한다

DNS A레코드를 가비아 공인 IP로 돌리면 Caddy가 발급·갱신까지 자동으로 한다.

```
api.example.com   A   <가비아 공인 IP>
```

> 이미 **구매한 SSL 인증서**가 있다면 자동 발급 대신 `.crt`/`.key`를 서버에 넣고 Caddyfile을 `tls /path/cert.crt /path/key.key`로 바꾼다.

## 8. 배포 후 반드시 확인하는 것

| # | 확인 | 왜 |
| --- | --- | --- |
| 1 | **SSE 챗봇 스트리밍** | 배포에서 가장 잘 깨진다. 안 되면 ASGI → Caddy `flush_interval` → 프록시 버퍼링 순으로 의심 |
| 2 | 프론트에서 실제 호출 | 커스텀 헤더(`x-visit-token`)가 CORS preflight에서 막히면 "로컬은 되는데 배포하면 401"이 된다 |
| 3 | `/api/schema/swagger-ui/` | 정적 파일(collectstatic)이 제대로 붙었는지 |
| 4 | 화보 폴링 반복 호출 | Redis가 실제로 물렸는지 (404가 나면 `REDIS_URL` 누락) |
| 5 | 버킷 CORS (PUT·GET) | 로컬은 same-origin이라 안 걸리고 **배포 후에 터진다** |

## 9. 8/28 철수

## 10. 아직 안 된 것

| 항목 | 상태 |
| --- | --- |
| **Celery 워커** | 리포트 생성이 아직 `threading.Thread`다. 화보 생성(15~40초 · 벤더 동시 한도)이 붙으면 스레드로는 동시 실행 제어가 안 되므로 Celery 복원이 필요하다. compose에 `worker` 서비스를 추가하면 된다 |
| **업로드 스토리지** | `STORAGE_BACKEND=dev`라 presign URL이 가짜다. Cloudflare R2(무료 10GB · S3 호환)를 권장. `STORAGE_BACKEND=s3` + 키 4개를 채우고 `pip install boto3` |
| **미디어 서빙** | R2를 쓰면 불필요. 서버 디스크에 둘 경우 Caddy에 `/media/*` 라우팅 추가 |
| `VISIT_STALE_AFTER` | 명세는 3시간인데 코드에 반영되지 않았다 |

## 11. 트래픽 1TB

완성 화보를 서버에서 직접 서빙하면 트래픽이 여기서 빠진다. R2를 쓰면 이미지 트래픽이 서버를 지나가지 않아 1TB를 API에만 쓸 수 있다. 데모 규모에서 넘칠 일은 없지만, 화보가 SNS로 퍼지는 시나리오라면 R2가 안전하다.
