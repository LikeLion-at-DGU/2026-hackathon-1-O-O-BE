# 직접 테스트하는 방법

지금까지 만든 것을 손으로 확인하는 순서. Swagger를 처음 쓰는 사람 기준으로 적었다.
최종 수정 2026-08-12 · 대상: `POST /enter` · `GET /products/{id}` · `POST /events` · `POST·GET /chat/messages` · `POST /chat` · `POST /admin/auth`

---

## 0. 준비 (2분)

터미널을 열고(맥: `Cmd + Space` → "터미널") 아래를 붙여넣는다.

```bash
cd ~/Downloads/O\&OBB/oando && source venv/bin/activate && python manage.py migrate && python manage.py seed_demo && python manage.py runserver
```

`Starting development server at http://127.0.0.1:8000/` 가 보이면 성공. **이 창은 그대로 둔다** (닫으면 서버가 꺼진다. 중지는 `Ctrl + C`).

curl로 테스트할 때는 `Cmd + T`로 **새 탭**을 열어서 거기서 명령을 실행한다. 첫 창은 서버가 쓰고 있어서 명령을 받지 못한다.

`.env`에 `OPENAI_API_KEY`가 들어 있어야 챗봇(5장)이 동작한다. 없으면 다른 건 다 되고 챗봇만 `LLM_UNAVAILABLE`이 나온다.

## 1. Swagger로 훑어보기 (설치 없이)

브라우저에서 http://127.0.0.1:8000/api/schema/swagger-ui/

`Visit` `Product` `Event` `Chat` `Admin` 태그별로 접혀 있다. 각 항목을 누르면 요청·응답 형식과 예시가 나온다.

### 사용법 3단계
1. 항목을 펼치고 오른쪽 **`Try it out`** 클릭 → 입력칸 활성화
2. 값을 채우고 파란 **`Execute`**
3. 아래 **`Response body`**에서 결과 확인. **`Curl`** 박스에는 같은 요청의 curl 명령이 생성돼 있다 (프론트에 그대로 전달 가능)

### 토큰 한 번만 넣기
`POST /api/v1/enter`를 먼저 실행해 응답의 `visit_token`을 복사한 뒤,
화면 **우측 상단 `Authorize`** → `VisitToken` 칸에 붙여넣기 → `Authorize` → `Close`.

이제 모든 요청에 `X-Visit-Token` 헤더가 자동으로 붙는다.

> ⚠️ `POST /events`와 `POST /chat/messages`는 `X-Anonymous-UUID` 헤더도 필요하다. Swagger 화면의 해당 입력칸에 `/enter` 응답의 `anonymous_uuid`를 넣는다.

## 2. 시안 흐름 그대로 따라가기 (핵심 시나리오)

터미널 새 탭에서 순서대로 실행한다. **1번에서 받은 값 3개를 계속 쓴다.**

### ① 입장

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/enter \
  -H "Content-Type: application/json" \
  -d '{"age_band":"20s","gender":"female"}' | python3 -m json.tool
```

확인할 것
- `anonymous_uuid` — **복사해둔다** (이탈 복구용)
- `visit_token` — **복사해둔다** (모든 API 열쇠)
- `visit_id` — **복사해둔다**
- `resumed: false` (새 방문)
- `scenes`에 진열대 4개 + 각 상품 2개, 상품마다 `no`가 붙어 있다

편의를 위해 셸 변수에 넣어두면 이후 명령이 짧아진다.

```bash
read -r AUUID TOKEN VID <<< $(curl -s -X POST http://127.0.0.1:8000/api/v1/enter \
  -H "Content-Type: application/json" -d '{"age_band":"20s","gender":"female"}' \
  | python3 -c "import json,sys; d=json.load(sys.stdin); print(d['anonymous_uuid'], d['visit_token'], d['visit_id'])")
echo "uuid=$AUUID / visit=$VID"
```

### ② 진열대 클릭 → 말풍선 적립

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/chat/messages \
  -H "Content-Type: application/json" -H "X-Visit-Token: $TOKEN" \
  -d "{\"visit_id\":\"$VID\",\"type\":\"scene_click\",\"scene_id\":\"sc_01\"}" | python3 -m json.tool
```

→ `201` + `content: "1번 진열대 클릭"` (문구를 서버가 만든다)

**같은 명령을 한 번 더 실행**하면 `200`이 온다 — 직전과 같은 클릭이라 말풍선을 새로 쌓지 않는다.

### ③ 상품 상세 조회

```bash
curl -s http://127.0.0.1:8000/api/v1/products/p_101 \
  -H "X-Visit-Token: $TOKEN" | python3 -m json.tool
```

확인할 것
- `preset_answers`에 `price`·`material`·`design_intent` 3개 (프리셋 버튼 문구)
- `external_url` (리포트의 '구매하기'가 갈 주소)
- **`llm_context`가 없어야 정상** (챗봇 프롬프트용 내부 필드)

### ④ 상품 클릭 + 프리셋 열람

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/chat/messages \
  -H "Content-Type: application/json" -H "X-Visit-Token: $TOKEN" \
  -d "{\"visit_id\":\"$VID\",\"type\":\"product_click\",\"product_id\":\"p_101\"}" >/dev/null

curl -s -X POST http://127.0.0.1:8000/api/v1/chat/messages \
  -H "Content-Type: application/json" -H "X-Visit-Token: $TOKEN" \
  -d "{\"visit_id\":\"$VID\",\"type\":\"preset_view\",\"product_id\":\"p_101\",\"preset_key\":\"price\"}" | python3 -m json.tool
```

→ 프리셋은 말풍선 **2개**를 만든다 (누른 버튼 `가격` + 답변). 응답으로는 답변이 온다.
**같은 프리셋을 다시 눌러도 매번 201** — 다시 물어보는 건 의미 있는 행동이라 중복 제거하지 않는다.

### ⑤ 행동 이벤트 전송 (분석용)

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/events \
  -H "Content-Type: application/json" -H "X-Visit-Token: $TOKEN" -H "X-Anonymous-UUID: $AUUID" \
  -d "{\"visit_id\":\"$VID\",\"events\":[
    {\"event_id\":\"$(uuidgen)\",\"event_type\":\"scene_view\",\"scene_id\":\"sc_01\",\"client_timestamp\":\"2026-08-12T09:00:00Z\"},
    {\"event_id\":\"$(uuidgen)\",\"event_type\":\"product_dwell\",\"product_id\":\"p_101\",\"client_timestamp\":\"2026-08-12T09:00:30Z\",\"metadata\":{\"dwell_ms\":30000}}
  ]}" | python3 -m json.tool
```

→ `202 {"accepted": 2, "duplicated": 0, "ignored": 0}`

**같은 명령을 다시 실행**하면 `event_id`가 새로 생성되므로 또 2건이 들어간다. 멱등성을 보려면 `$(uuidgen)` 대신 고정 문자열(`"11111111-1111-1111-1111-111111111111"`)을 쓰고 두 번 실행 → 두 번째는 `duplicated: 2`.

### ⑥ 타임라인 복원 (화면 이동·새로고침 시나리오)

```bash
curl -s "http://127.0.0.1:8000/api/v1/chat/messages?visit_id=$VID" \
  -H "X-Visit-Token: $TOKEN" | python3 -m json.tool
```

확인할 것
- 첫 줄이 챗봇 인사 (`role: assistant`) — 서버가 입장 시 넣어둔 것
- 클릭·프리셋이 시간순으로 있다
- `current_context: {"scene_id": "sc_01", "product_id": "p_101"}` — 챗봇이 쓸 문맥

## 3. 챗봇 (SSE 스트리밍)

**`-N` 옵션이 중요하다.** 없으면 스트림이 다 끝날 때까지 화면에 아무것도 안 나온다.

```bash
curl -N -X POST http://127.0.0.1:8000/api/v1/chat \
  -H "Content-Type: application/json" -H "X-Visit-Token: $TOKEN" \
  -d "{\"visit_id\":\"$VID\",\"message\":\"이 상품의 디자이너 의도를 설명해줘\"}"
```

이렇게 조각으로 흘러나오면 정상이다.

```
data: {"delta": "이 백팩은 "}
data: {"delta": "1976년 뮌헨의 "}
...
data: {"done": true, "message_id": "m_...", "recommendations": []}
```

**여기서 확인할 핵심** — 질문에 상품명이 없는데도 답이 나온다. 서버가 ④의 클릭 기록을 읽어 "지금 p_101 얘기 중"임을 알고 있기 때문이다.

가드레일도 확인해보자. 아래는 "매장 직원에게 확인해 보세요"가 나와야 정상이다.

```bash
curl -N -X POST http://127.0.0.1:8000/api/v1/chat \
  -H "Content-Type: application/json" -H "X-Visit-Token: $TOKEN" \
  -d "{\"visit_id\":\"$VID\",\"message\":\"지금 재고 있어? 할인 언제 해?\"}"
```

> Swagger에서도 호출은 되지만 스트리밍이 한 번에 뭉쳐 보인다. 조각이 흘러오는 걸 보려면 curl `-N`을 쓴다.

## 4. 이탈 복구 (이어하기) 테스트

**"퇴장을 누르지 않고 창을 닫았다"** 를 재현한다. 브라우저를 닫는 대신, 저장해둔 `anonymous_uuid`로 다시 입장하면 된다.

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/enter \
  -H "Content-Type: application/json" -H "X-Anonymous-UUID: $AUUID" \
  -d '{}' | python3 -m json.tool
```

확인할 것
- **`resumed: true`**
- `visit_id`·`visit_token`이 ①과 **완전히 같다** (저장해둔 토큰이 계속 유효하다는 뜻)
- `resumed_visit`에 `products_viewed`·`message_count` — 모달에 "상품 3개를 보던 중이었어요"를 띄울 값
- `anonymous_uuid`가 응답에 **없다** (재발급하지 않았으므로)

### "새로 시작"을 눌렀을 때

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/enter \
  -H "Content-Type: application/json" -H "X-Anonymous-UUID: $AUUID" \
  -d '{"force_new":true}' | python3 -m json.tool
```

→ `resumed: false` + 새 `visit_id`. 이전 방문은 닫힌다(리포트는 만들지 않는다).

### 30분이 지난 경우

30분을 기다릴 수 없으니 시간을 조작한다. **서버가 아닌 새 탭**에서:

```bash
cd ~/Downloads/O\&OBB/oando && source venv/bin/activate && python manage.py shell -c "
from django.utils import timezone; from datetime import timedelta
from apps.visits.models import Visit
n = Visit.objects.filter(ended_at__isnull=True).update(last_seen_at=timezone.now()-timedelta(minutes=31))
print(f'{n}개 방문을 31분 전으로 되돌림')"
```

이제 다시 입장하면 `resumed: false`가 나온다 (이어하기 시간이 지났으므로 새 방문).

## 6. 에러 응답 확인 (프론트에 넘길 형식)

모든 에러가 같은 모양인지 보는 게 목적이다.

```bash
# 400 — 없는 연령대
curl -s -X POST http://127.0.0.1:8000/api/v1/enter -H "Content-Type: application/json" -d '{"age_band":"70s"}'

# 401 — 토큰 없음
curl -s http://127.0.0.1:8000/api/v1/products/p_101

# 401 — 위조 토큰
curl -s http://127.0.0.1:8000/api/v1/products/p_101 -H "X-Visit-Token: garbage"

# 404 — 없는 상품
curl -s http://127.0.0.1:8000/api/v1/products/p_999 -H "X-Visit-Token: $TOKEN"

# 400 — 대상이 빠진 이벤트 (product_view에 product_id 없음)
curl -s -X POST http://127.0.0.1:8000/api/v1/events \
  -H "Content-Type: application/json" -H "X-Visit-Token: $TOKEN" -H "X-Anonymous-UUID: $AUUID" \
  -d "{\"visit_id\":\"$VID\",\"events\":[{\"event_id\":\"$(uuidgen)\",\"event_type\":\"product_view\",\"client_timestamp\":\"2026-08-12T09:00:00Z\"}]}"

# 403 — 남의 방문에 기록 시도
curl -s -X POST http://127.0.0.1:8000/api/v1/chat/messages \
  -H "Content-Type: application/json" -H "X-Visit-Token: $TOKEN" \
  -d '{"visit_id":"v_someone_else","type":"scene_click","scene_id":"sc_01"}'
```

전부 이 형태여야 한다.

```json
{ "error": { "code": "VALIDATION_ERROR", "message": "...", "detail": { "필드명": ["설명"] } } }
```

## 8. 트러블슈팅

| 증상 | 원인·해결 |
| --- | --- |
| `404` + HTML 페이지가 나온다 | URL 끝에 슬래시를 붙였는지 확인. `/api/v1/enter` (O) / `/api/v1/enter/` (X) |
| `JSON parse error` | 바디가 비었다. 건너뛰기도 `-d '{}'`는 보내야 한다 |
| `429 RATE_LIMITED` | 챗봇 분당 20회 제한. 1분 기다리거나 서버를 재시작한다(캐시가 메모리라 초기화된다) |
| `403 이미 종료된 관람입니다` | 그 방문은 닫혔다. `/enter`로 새로 입장한다 |
| 챗봇이 `LLM_UNAVAILABLE` | `.env`의 `OPENAI_API_KEY`가 비었다. 넣고 **반드시 서버 재시작** — 설정은 기동할 때 한 번만 읽는다 |
| `Error: That port is already in use.` | 이전 서버가 아직 8000을 잡고 있다. **이게 제일 헷갈리는 함정** — 새 서버는 죽고 요청은 옛 서버로 가서 옛 설정(키 없던 시절)으로 응답한다. `pkill -f "manage.py runserver"` 후 다시 띄운다 |
| 챗봇 응답이 한 번에 뭉쳐 나온다 | curl에 `-N`을 붙인다 |
| `/events`가 400 `X-Anonymous-UUID` | 이 API는 헤더 2개가 필수다 (명세 요구사항) |
| 처음부터 다시 하고 싶다 | 서버 끄고 `rm db.sqlite3*` → `migrate` → `seed_demo` → 관리자 계정 재생성 |

## 9. 체크리스트

- [ ] 이어하기 모달에 띄울 정보(`products_viewed`·`message_count`)가 충분한가
- [ ] 에러 메시지가 사용자에게 그대로 보여줘도 되는 문장인가
