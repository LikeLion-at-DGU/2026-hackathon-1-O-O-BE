설명

관람을 마치면 호출한다. 서버는 분석 작업을 대기열에 넣기만 하고 리포트 주소(slug)를 발급해 즉시 돌려준다. 분석이 3~4초 걸리더라도 사용자는 기다리지 않는다. 같은 visit_id로 다시 호출해도 같은 slug를 준다(멱등).

퇴장 설문은 받지 않는다. 연령대·성별도 입장할 때(POST /enter) 이미 받았으므로 여기서는 아무것도 입력받지 않는다.

AI ② — 리포트·데이터 생성 (비동기 워커)

이 API가 큐에 넣은 작업을 워커가 처리한다. 대화 내역 + 행동 데이터(조회·재조회·체류시간·챗봇 질문 수·전시존 이동)를 종합해 리포트를 만들며, 이게 기업에 파는 B2B 데이터 자산이자 추천 서비스의 입력이 된다.

채팅 요약 화면을 따로 만들지 않기로 했으므로, 대화에서 뽑은 내용은 전부 이 리포트 안에 녹여 넣는다.

워커 파이프라인

단계하는 일왜
① 이벤트 집계상품·전시존별 조회·재조회·체류·챗봇 수수백 개 이벤트를 상품 단위로 압축
② 관심도 산출log 가중합한 상품만 30번 본 사람이 프로필을 지배하지 않게
③ confidence신호 총량 평가데이터가 적을 때 틀린 개인화를 피하려고
④ 취향 벡터관심 상품의 카테고리·색상·소재·스타일·가격대 합산. 챗봇 선호는 가산, 비선호는 감점개별 상품 선호를 속성 선호로 변환
⑤ 스코어링전체 상품 대상 개인 취향 75% + 인기 15% + 신상품 10%, 안 본 상품엔 발견 가산관심을 안 본 상품까지 확장
⑥ 16유형 매핑4축 점수 → 16유형(결정론적)복잡한 벡터를 한 마디로 압축
⑦ 리포트 조립payload 확정 → status: ready결과를 박제해 영구 조회 가능하게

①~⑦은 순수 연산이라 10ms 미만. LLM이 붙는 두 단계만 3~4초 걸린다.

  • ③′ 취향 추출 — 챗봇 대화를 구조화 태그로 (행동에 안 드러나는 망설임을 잡으려고)
  • ⑦′ 문장 생성 — 추천 이유·캐릭터 서술 (같은 유형이어도 "나 맞네"가 나오게)
