행동 이벤트 수집 (배치)

API Endpoint/api/v1/events
HTTP methodPOST
메모모았다가 한번에 전송. event_id로 중복 제거, 원본 그대로 쌓기만 함
파트Event

설명

프론트가 모아둔 행동 기록을 한번에 묶어서 보낸다. 매 클릭마다 서버를 치지 않고, 주기적으로 또는 페이지를 떠날 때 보내서 브라우저가 닫혀도 직전 기록이 날아가지 않게 한다.

저장은 append-only — 쌓기만 하고 고치지 않는다. 같은 이벤트를 두 번 보내도 event_id로 걸러 한 번만 저장하므로(멱등), 실패하면 그냥 재전송하면 된다.

Request

헤더: X-Visit-Token ✅, X-Anonymous-UUID ✅

필드타입필수설명
visit_idstring✅대상 방문
eventsarray✅이벤트 배열

events 항목

필드타입필수설명
event_idstring(UUID)✅클라이언트가 생성. 중복 제거 키
event_typestring✅아래 표 참고
client_timestampstring(ISO8601)✅클라에서 일어난 시각
scene_idstring❌전시존 대상 이벤트일 때
product_idstring❌상품 대상 이벤트일 때
metadataobject❌dwell_ms(체류시간) 등

이벤트 타입별 역할

매장 / 방문

event_type언제어떤 역할인지
store_enter입장 버튼을 눌러 들어왔을 때관람의 시작점. 퍼널 계산의 분모가 된다
visit_start방문이 시작될 때체류시간 측정의 기준 시각
visit_end관람이 끝났을 때총 체류시간 확정. 리포트 분석의 신호

전시존 (매대)

event_type언제어떤 역할인지
scene_view전시존 화면에 들어갔을 때어떤 존이 사람을 끌어당기는지 (유입)
scene_dwell그 존에 머문 시간어떤 구역에 관심이 쏠리는지. 진열 구성 개선 근거
hotspot_click존 안의 상품 핫스팟을 눌렀을 때존에서 상품으로 넘어간 전환. 진열이 잘 먹혔는지

상품 (취향 분석의 핵심 재료)

event_type언제어떤 역할인지
product_view상품 상세를 열었을 때기본 관심 신호. 가장 약한 가중치
product_dwell그 상품에 머문 시간가장 중요한 신호. 오래 볼수록 관심이 크다고 본다
product_save찜(하트)을 눌렀을 때의도가 명확한 강한 신호. 높은 가중치
product_compare두 상품을 비교했을 때구매 직전 고민 신호. 브랜드엔 "자주 비교되는 조합" 데이터
같은 상품을 다시 본 횟수(재조회)도 product_view가 여러 번 쌓이는 걸로 계산한다. 한 번 오래 본 것과 여러 번 돌아온 것 모두 관심으로 친다.

챗봇

event_type언제어떤 역할인지
chatbot_open챗봇을 열었을 때정보를 더 원한다는 신호
question_submit질문을 보냈을 때무엇을 궁금해하는지. 행동으로 안 드러나는 취향·망설임을 잡는 통로
recommendation_impression챗봇이 추천을 띄웠을 때추천이 실제로 노출됐는지 (클릭률의 분모)
recommendation_click그 추천을 눌렀을 때추천이 먹혔는지. 추천 로직 성능 측정

(피팅 관련 이벤트는 이번 스코프에 없음)
