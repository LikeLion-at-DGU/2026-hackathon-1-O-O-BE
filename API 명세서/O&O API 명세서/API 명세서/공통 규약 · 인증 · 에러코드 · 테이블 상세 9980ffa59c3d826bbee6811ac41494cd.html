파트공통

기본 규칙

항목내용
Base URLhttps://api.oando.example/api/v1 (예시)
포맷요청·응답 모두 application/json, UTF-8
인증사용자 API는 로그인 없음. anonymous_uuid • visit_token 헤더 사용. /admin/*만 Bearer 인증
매장매장은 하나로 고정. 매장 지정 파라미터를 받지 않고 서버가 기본 매장을 붙인다
Stateless서버 메모리에 세션·대화 상태를 두지 않고 매 요청 DB에서 조회
멱등성/events는 event_id, /finish는 visit_id 기준으로 중복 요청 무시 (같은 결과 반환)
시간client_timestamp(클라 발생) + server_received_at(서버 수신) 둘 다 저장. ISO 8601 / UTC

공통 요청 헤더

헤더필수설명
Content-Type: application/json✅
X-Anonymous-UUID조건부클라이언트가 보관하는 익명 UUID. 최초 진입 시에는 생략 가능
X-Visit-Token조건부/enter 응답으로 받은 토큰. 그 이후 모든 사용자 API에 필요
Authorization: Bearer <token>조건부/admin/* 전용

테이블 컬럼 상세

테이블핵심 컬럼
productsid, name, features(구조화 피처), llm_context(자연어 설명), price, color, material, images, story, scene_id
storesid, name, scenes(전시존 구성)
usersanonymous_uuid, age_band, gender, created_at
visitsid, user_id, started_at, ended_at
eventsevent_id, visit_id, event_type, scene_id/product_id, client_timestamp, server_received_at, metadata
chat_logsvisit_id, message_id, role(assistant/user_action/user/preset), content, scene_id, product_id, created_at
taste_profilesuser_id, vector, axis_scores, character_type, confidence, updated_at
reportsslug, visit_id, user_id, payload(JSON), status(pending/ready), created_at
products.preset_answersprice / material / design_intent 미리 작성해 둔 문구 (LLM 생성 아님)
제외 확정: fitting_sessions(피팅), exit_survey(퇴장 설문) 테이블은 만들지 않는다.

운영 원칙

  • 원본 이벤트는 수정하지 않고(append-only), 분석 파생 데이터는 별도로 생성한다. 추천 로직을 바꿔도 원본으로 재분석할 수 있다.
  • 워커는 재시도·지수 백오프·멱등 처리·실패 보관(DLQ)으로 유실과 중복 집계를 방지한다.
  • 모든 추천·유형·리포트 결과에 근거와 confidence를 함께 제공한다.
  • 개인정보는 최소로 수집한다(기본값 익명 UUID). chat_logs는 마스킹·보존기간을 적용한다.
