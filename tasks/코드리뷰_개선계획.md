## 4. API 계약 테스트 16개 설계

전부 실제 URL 라우팅 경유(`APITestCase`/`APIClient`), 통일 에러 포맷 `{"error":{code,...}}` 단언 포함.

| # | 테스트 | 없을 때 생기는 회귀 |
|---|---|---|
| 1 | enter 신규: 무헤더 POST → 201 + visit_token·scenes·muse_no | 입장 응답 계약 파손을 프론트 흰 화면으로야 발견 |
| 2 | enter 이어하기: 같은 X-Anonymous-UUID 재입장 → is_resumed=true | 재방문자에게 새 뮤즈번호가 발급돼 타임라인 유실 |
| 3 | enter force_new: 기존 visit expire + 새 visit | "새로 시작"이 기존 세션을 못 닫아 이어하기 모달 무한 재출현 |
| 4 | 토큰 누락: X-Visit-Token 없이 /events → 401 | 퍼미션 실수(AllowAny)로 전 엔드포인트 공개돼도 무감지 |
| 5 | 위조 토큰: 임의 문자열 → 401 INVALID_VISIT_TOKEN 코드 | 에러 코드 계약이 바뀌어 프론트 에러 분기 전부 오작동 |
| 6 | 만료 토큰: last_seen 3h 경과 → 401 | 만료 로직 회귀로 좀비 세션이 무한 유지 |
| 7 | IDOR-visit: A 토큰 + B의 visit_id로 /events → 403 | 타인 방문에 이벤트 주입 → 남의 리포트 오염 |
| 8 | IDOR-report: A 토큰으로 B report의 candidates → 403 | slug 유출 시 타인 화보 후보·생성 권한 탈취 |
| 9 | event 멱등: 동일 event_id 2회 → duplicated=1, DB 1행 | 새로고침·재전송이 체류시간을 2배로 부풀림 (현재 프론트 dwell 3중 전송의 마지막 방어선) |
| 10 | dwell 상한: dwell_ms=9,000,000 → 300,000으로 clamp | 탭 방치 하나가 대시보드 상품 지표를 지배 |

## 5. 구현 가이드 (코드 없음 — 방향·파일·검증)

**a) FAKE 이미지 정적파일 의존 제거** — [worker.py](apps/lookbook/worker.py) FAKE 분기가 정적 URL 상수를 반환하는 대신, 단색 캔버스 바이트를 만들어 기존 `compose.build()` → `storage.save_public()` 경로를 그대로 태워 **실제 파일을 생성**하게 한다. `FAKE_IMAGE_URL` 상수 삭제. 검증: 새 디렉터리에 클론 → `.env.example` 복사 → migrate → seed → 화보 E2E 후 `image_url` GET 200.

**b) purge timer 코드화** — `deploy/oando-purge-uploads.service`(`manage.py purge_uploads` oneshot, User=oando) + `.timer`(OnCalendar=hourly) 추가, `deploy/README.md`에 설치·확인 절차 기록. 서버 설치는 §6.

**c) deploy-oando 편입** — 서버 사본을 `sudo -u oando cat`으로 받아 시크릿·호스트 고유값이 없는지 확인 후 `deploy/deploy-oando.sh`로 커밋, [deploy.yml](.github/workflows/deploy.yml)에 "서버의 /usr/local/sbin/deploy-oando는 이 파일의 사본" 주석. 검증: `bash -n deploy/deploy-oando.sh`.

**d) CI 게이트** — 이미 작업 트리 deploy.yml에 test job 존재 → 작업 1 커밋에 포함하고 **push 후 Actions 첫 실행이 녹색인지 확인**하는 것까지가 완료 조건.

**e) 문서·.env.example 정합** — compose 블록 삭제(POSTGRES_* 는 "서버 systemd 환경 전용" 주석으로 이동), 필드_가이드의 funnel/products는 작업 1 커밋 후 사실이 되므로 응답 예시만 실제 구현과 대조.

**f) upload rate limit** — `DEFAULT_THROTTLE_RATES`에 `"upload"` 스코프 추가, `UploadPresignView`·`UploadReceiveView`에 `ScopedRateThrottle`. presign은 visit 단위, receive는 IP 단위(무인증이므로). 검증: 테스트에서 한도+1회 요청 → 429.

**g) on_commit** — [analysis/services.py](apps/analysis/services.py)의 `finish()`가 트랜잭션 안에서 `enqueue()`를 직접 부르지 않도록 `transaction.on_commit` 콜백으로 이동. lookbook 접수 후 `worker.enqueue()`도 동일. 주의: `TestCase` 안에서는 on_commit이 실행되지 않으므로 관련 테스트는 `captureOnCommitCallbacks`로 작성. 검증: 전체 테스트 통과 + finish E2E에서 리포트 ready 재확인.

**h) 작업 유실 복구 — 판단** — Lookbook은 job 상태가 캐시 TTL(300s)로 자연 소멸해 클라이언트가 재시도 UI를 받으므로 치명도가 낮고, Report는 PROCESSING 컬럼 신설(새 마이그레이션)이 필요해 시간 대비 점수 효과가 작다. **12h 예산이면 작업 10(Lookbook 재큐 경로만), 8h 예산이면 전체 보류**하고 재배포를 생성 트래픽 없는 시점으로 통제하는 운영 규칙으로 대체한다.

**i) 대시보드** — 작업 트리에 funnel/products 구현·테스트 완료 상태이므로 **"구현" 선택**, 작업 1 커밋에 포함. 문서 제거 불필요. (MCM용 대시보드 프론트는 별도 링크 배포 예정 — 본 계획 범위 밖.)

**시크릿 관련** — 레포 밖 OneDrive 동기화 폴더의 OpenAI 키·DB 비밀번호 평문 파일은 코드리뷰 점수와 무관하지만 즉시 조치 권장: 새 키 발급 → 서버 `.env` 교체 → 서비스 재시작 확인 → 구 키 폐기 → 파일 삭제 순서(데모 중단 없음). 값은 어디에도 출력·기록하지 않는다.
