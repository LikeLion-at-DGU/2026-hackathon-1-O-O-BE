## 1. 기반 결정

### 1-1. SQLite로 간다 — 대신 보완이 필요하다

SQLite는 **쓰기가 DB 전체를 잠근다.** 리포트 워커가 백그라운드에서 쓰는 동안 `/events` 배치가 들어오면 `database is locked`가 납니다. 아래 3개는 선택이 아니라 필수입니다.

- [ ] **WAL 모드 + timeout** — 읽기와 쓰기가 서로를 막지 않게 합니다

```python
# config/settings.py
DATABASES = {
    "default": {
        "ENGINE": "django.db.backends.sqlite3",
        "NAME": BASE_DIR / "db.sqlite3",
        "OPTIONS": {"timeout": 20},   # lock 만나면 20초 재시도
    }
}

# apps/catalog/apps.py 또는 config/__init__.py — 연결마다 PRAGMA 적용
from django.db.backends.signals import connection_created

def _sqlite_pragmas(sender, connection, **kwargs):
    if connection.vendor == "sqlite":
        cursor = connection.cursor()
        cursor.execute("PRAGMA journal_mode=WAL;")
        cursor.execute("PRAGMA synchronous=NORMAL;")

connection_created.connect(_sqlite_pragmas)
```

> Django 5.1+ 라면 `OPTIONS`에 `init_command`로 PRAGMA를 직접 넣을 수 있습니다. 버전 확인 후 둘 중 하나만 쓰세요.

- [ ] **워커 트랜잭션을 짧게** — 분석 계산(순수 함수)을 전부 끝낸 뒤, 마지막에 `Report` 저장 한 번만 `transaction.atomic()`. 계산 도중 트랜잭션을 열어두면 그 시간만큼 전체가 잠깁니다.
- [ ] **집계·스코어링에 쓰는 축은 JSON이 아니라 컬럼으로** — SQLite는 JSON 내부 값으로 group by·집계를 하는 게 매우 아픕니다. `/admin/cohorts`가 색상·소재별 분포를 뽑아야 하므로 여기서 막힙니다.

```python
class Product(models.Model):
    id = models.CharField(primary_key=True, max_length=32)          # p_101
    scene = models.ForeignKey(Scene, related_name="products", on_delete=models.PROTECT)
    no = models.PositiveSmallIntegerField()                          # 씬 내 번호 (챗봇 안내용)
    name = models.CharField(max_length=200)
    price = models.PositiveIntegerField()
    external_url = models.URLField()                                 # 구매하기 → 본사 사이트
    story = models.TextField()

    # 스코어링·코호트 집계 축 → 전부 컬럼 + TextChoices
    category = models.CharField(max_length=20, choices=Category.choices)
    color = models.CharField(max_length=20, choices=Color.choices)
    material = models.CharField(max_length=20, choices=Material.choices)
    pattern = models.CharField(max_length=20, choices=Pattern.choices)
    silhouette = models.CharField(max_length=20, choices=Silhouette.choices)
    mood = models.CharField(max_length=20, choices=Mood.choices)
    price_band = models.CharField(max_length=10, choices=PriceBand.choices)
    use_case = models.CharField(max_length=20, choices=UseCase.choices)
    is_new = models.BooleanField(default=False)                       # 신상품 점수 10%

    images = models.JSONField(default=list)                          # URL 목록
    preset_answers = models.JSONField(default=dict)                  # price/material/design_intent
    llm_context = models.TextField()                                 # ⚠️ 응답에 절대 내리지 않음

    class Meta:
        constraints = [models.UniqueConstraint(fields=["scene", "no"], name="uniq_scene_product_no")]
```

`features` JSON 컬럼은 두지 않습니다. **위 8개 컬럼이 곧 features입니다.**

### 1-2. `visit_token` = DB 토큰

```python
class Visit(models.Model):
    id = models.CharField(primary_key=True, max_length=32)           # v_9f8e...
    visitor = models.ForeignKey(Visitor, related_name="visits", on_delete=models.CASCADE)
    token = models.CharField(max_length=64, unique=True, db_index=True)  # token_urlsafe(24)
    started_at = models.DateTimeField(auto_now_add=True)
    last_seen_at = models.DateTimeField(auto_now_add=True)           # 이어하기 판정용
    ended_at = models.DateTimeField(null=True, blank=True)
```

- 인증은 `api/authentication.py`의 `VisitTokenAuthentication` 한 곳에서만. `ended_at`이 찍힌 Visit의 토큰은 **읽기만 허용**(리포트 폴링), `/events`·`/chat`은 거부.
- **`last_seen_at`을 매 요청마다 UPDATE 하지 마세요.** SQLite에서 쓰기가 늘면 그대로 lock 위험입니다. `POST /events`(배치는 주기적으로 옵니다)와 `POST /chat`에서만 갱신하면 이어하기 판정에 충분합니다.

### 1-3. `AUTH_USER_MODEL`은 건드리지 않는다 — `AdminUser` 모델도 만들지 않는다

앞서 "`admin_users` 모델이 누락됐다"고 지적했는데, **매장이 하나로 고정**이라는 조건을 넣으면 결론이 바뀝니다. 격리할 브랜드가 하나뿐이라 커스텀 유저 모델의 값이 없습니다.

- [ ] `AUTH_USER_MODEL` 설정하지 않음 (Django 기본 `auth.User`)
- [ ] `POST /admin/auth`는 `authenticate()` + `djangorestframework-simplejwt`로 토큰 발급
- [ ] 응답의 `store_ids`는 고정 매장 1개를 그대로 반환 (`settings.DEFAULT_STORE_ID`)
- [ ] 관리자 계정은 `createsuperuser`로 생성. `is_staff=True`인 유저만 `/admin/*` 통과시키는 퍼미션 하나만 둠
- [ ] `dashboard/models.py` 불필요 → `dashboard/`에 `migrations/`도 없음

`Visitor`(익명 방문자)와 `User`(관리자)는 이름이 겹치지 않으므로 혼동도 없습니다.

### 1-4. Celery를 걷어낸다

SQLite + 3~4초 작업이라는 조건에서 `redis + worker + beat`는 얻는 것 없이 죽을 지점만 늘립니다.

- [ ] `config/celery.py`, `config/__init__.py`의 celery import 삭제
- [ ] `analysis/services.enqueue()`가 `threading.Thread(target=..., daemon=True).start()`로 실행
- [ ] 스레드 안에서 예외가 나면 `Report.status`를 `failed`로 기록하고 로깅 (조용히 죽으면 사용자가 영원히 pending을 봅니다)
- [ ] `GET /reports/{slug}`는 `failed`일 때 사용자에게 재시도 안내를 줄 수 있게 상태를 그대로 노출

> `status`는 명세상 `pending`/`ready` 2개였습니다. **`failed` 추가는 프론트 계약 변경**이니 통보 대상(§6).

## 2. 진행 중 Visit 이어하기 (새 기능)

익명 UUID를 쓰는 이유가 "로그인 없는 편의성"만이 아니라 **"퇴장 전에 잘못 껐어도 이어서 하고, 퇴장을 눌러 리포트를 받는다"** 이므로 아래를 구현합니다.

### 설계 — 왕복을 늘리지 않는다

`POST /enter` 하나로 처리합니다. 별도 조회 엔드포인트를 만들지 않습니다.

```
POST /api/v1/enter
헤더: X-Anonymous-UUID (있으면)
바디: { "age_band": "20s", "gender": "female", "force_new": false }
```

| 상황 | 서버 동작 | 응답 |
| --- | --- | --- |
| UUID 없음 | Visitor 발급 + Visit 생성 | `resumed: false` + `anonymous_uuid` |
| 진행 중 Visit 있음 (`ended_at` null, `last_seen_at` 30분 내) | **그 Visit·그 토큰을 그대로 반환** | `resumed: true`, `resumed_visit{started_at, products_viewed, message_count}` |
| 미종료지만 30분 초과 | 그 Visit을 만료 처리(`ended_at` 기록, 리포트 생성 X) 후 새 Visit | `resumed: false` |
| `force_new: true` | 진행 중 Visit을 만료 처리하고 새 Visit | `resumed: false` |

- 프론트는 `resumed: true`를 받으면 **"이어서 볼까요? / 새로 시작"** 모달을 띄웁니다. 이미 이어진 상태이므로 "이어서"는 아무것도 호출하지 않고, "새로 시작"만 `force_new: true`로 재호출합니다.
- `resumed_visit`에 요약(본 상품 수·메시지 수)을 주는 이유: 모달에 "3개 상품을 보던 중이었어요"를 띄울 수 있어야 이어할 이유가 생깁니다.
- 이어한 뒤 프론트는 `GET /chat/messages?visit_id=`로 타임라인을 복원합니다. **이미 있는 API이므로 추가 작업이 없습니다.**
- 이어할 때 `age_band`/`gender`는 **덮어쓰지 않습니다.** 첫 입장 값을 유지합니다(이미 답한 걸 다시 묻지 않음).

### 상수

```python
VISIT_STALE_AFTER = timedelta(hours=3)   # 토큰 만료 = 이어하기 허용 시간 (입장 시각 기준)
```

### 만료를 배치로 처리하지 않는 이유
판정을 `/enter` 시점에 계산하므로 스케줄러가 필요 없습니다. (`close_stale_visits`를 삭제하라고 한 판단은 이 기능이 들어와도 유효합니다.)

### 한계 — 프론트 안내 필요
UUID는 브라우저 저장소(localStorage)에 있습니다. 시크릿 모드·저장소 삭제·다른 기기에서는 복구되지 않습니다.

## 3. 계약 구멍 해결

### 3-1. 리포트가 집에서 안 열리는 문제 → payload에 상품 스냅샷 박제

`recommendations`에 `product_id`만 있으면 리포트 화면이 상품명·이미지·가격을 못 그립니다. 집에서는 `visit_token`이 없어 `GET /products/{id}`가 401이기 때문에 **우회로가 없습니다.**

- [ ] 워커 ⑦단계에서 상품 정보를 **복사해 넣는다**

```json
{
  "status": "ready",
  "character": { "type_code": "CNPD", "name": "클래식 미니멀리스트", "one_liner": "절제된 무드를 즐기는 타입" },
  "top_keywords": ["블랙", "레더", "미니멀"],
  "hero": {
    "product_id": "p_204", "name": "Stark 백팩", "thumbnail": "https://.../t.jpg",
    "price": 890000, "external_url": "https://mcm.com/...",
    "reason": "선호 소재(레더)와 일치", "score": 0.87
  },
  "recommendations": [ { "product_id": "...", "name": "...", "thumbnail": "...", "price": 0,
                         "external_url": "...", "reason": "...", "score": 0.0, "is_viewed": false } ],
  "interested": [ { "product_id": "...", "name": "...", "thumbnail": "...", "reason": "체류 30초 + 재조회 2회" } ],
  "confidence": 0.62,
  "visit_summary": { "scenes_viewed": 4, "products_viewed": 9, "questions": 3 }
}
```

- `hero`를 따로 둡니다. "가장 적합한 상품 1개를 크게 노출"이 기획 화면 구성이므로 프론트가 배열 0번을 꺼내 쓰는 암묵적 규칙보다 명시적인 게 낫습니다.
- `is_viewed`로 "관심 있게 본 상품"과 "새로 추천된 상품"을 한 그리드에서 구분합니다(기획 화면 요구).
- 박제이므로 나중에 상품 가격이 바뀌어도 리포트는 그대로입니다. 이게 의도된 동작입니다.

### 3-2. 구매하기 링크 → `Product.external_url` 추가
크롤링을 직접 하니 **원본 상품 페이지 URL을 같이 긁으면 공짜로 해결**됩니다. 크롤링 스펙에 넣어주세요.

### 3-3. `GET /reports/{slug}`는 무인증 공개
집에서 열려야 하므로 slug가 곧 열쇠입니다(capability URL). 대신:
- [ ] slug는 `secrets.token_urlsafe(16)` 이상 (짧게 만들지 마세요 — 열거 가능해집니다)
- [ ] 응답에 `X-Robots-Tag: noindex` (검색엔진에 리포트가 걸리면 사고입니다)
- [ ] 리포트에는 개인 식별 정보를 담지 않는다 — 이미 익명이라 자연히 충족됩니다

### 3-4. 챗봇 카드 추천의 후보를 서버가 고른다

`POST /chat` 시점엔 `taste_profile`이 없습니다(그건 `/finish` 이후 생김). 그래서 **LLM 호출 전에 서버가 규칙으로 후보를 고릅니다.**

```
후보 선정 (chat/services.py, LLM 호출 전)
  1. 현재 문맥 상품(current_context.product_id)을 기준으로 잡는다
  2. color·material·mood·price_band·category 중 일치 개수로 점수 (+가중치는 material > mood > color)
  3. 이번 Visit에서 이미 상세를 본 상품은 제외 (새로운 발견을 주려고)
  4. 상위 3개만 → 프롬프트에 name·scene_no·product_no·핵심 속성만 넣는다
```

- 프롬프트 제약: **"추천은 아래 후보 목록에 있는 상품만, 주어진 번호로만 언급한다. 목록에 없는 상품이나 번호를 만들지 않는다."** 없는 진열대 번호를 말하면 매장에서 즉시 들통납니다.
- 응답 `done` 이벤트의 `recommendations`는 **LLM 출력이 아니라 서버가 고른 후보 그대로** 내려줍니다. LLM이 텍스트에서 일부만 언급했더라도 카드는 서버 기준으로 일관됩니다.
- 문맥 상품이 아직 없을 때(입장 직후 바로 채팅)는 후보를 비우고 `recommendations: []`로 둡니다. 억지 추천은 하지 않습니다.

### 3-5. `product_compare` 이벤트를 없애고 서버가 추론한다

프론트에 비교 UI가 없어서 이벤트가 안 들어오면 `/admin/products`의 "자주 비교한 상품 조합"이 빈칸이 됩니다. 프론트 작업을 늘리지 않고 지표를 살리는 방법:

- [ ] 이벤트 타입에서 `product_compare` **삭제**
- [ ] 대시보드에서 `product_view` 순서로 파생 계산 — **같은 Visit에서 두 상품을 60초 안에 번갈아 조회(A→B→A 또는 A→B 왕복)** 하면 비교로 본다
- [ ] "자주 비교한 조합"은 그 쌍을 Visit 단위로 집계

행동의 정의를 문서에 적어두는 조건으로, 실제 사용자 행동에 더 가깝습니다(비교 버튼을 누르는 사람은 거의 없습니다).

## 4. 데이터 규격 (상품 30개 크롤링 기준)

### 4-1. `features` 분류 체계 — 확정안

**이 목록 밖의 값은 넣지 않습니다.** "블랙"과 "검정"이 섞이면 취향 벡터 비교가 성립하지 않습니다. 크롤링 후 사람이 매핑하는 작업이 반드시 들어갑니다.

| 축 | 값 | 개수 |
| --- | --- | --- |
| `category` | `backpack` `tote` `crossbody` `shoulder` `wallet` `accessory` | 6 |
| `color` | `black` `white` `cognac` `beige` `navy` `red` `pink` `metallic` `visetos_mix` | 9 |
| `material` | `coated_canvas` `smooth_leather` `grained_leather` `nylon` `suede` `mixed` | 6 |
| `pattern` | `visetos_monogram` `logo_print` `solid` `studded` | 4 |
| `silhouette` | `structured` `slouchy` `boxy` `compact` | 4 |
| `mood` | `classic_heritage` `minimal` `y2k_street` `bold_statement` | 4 |
| `price_band` | `entry`(60만 미만) `mid`(60~120만) `high`(120만 초과) | 3 |
| `use_case` | `daily` `work` `travel` `going_out` | 4 |

`mood`에 `y2k_street`를 넣은 건 의도적입니다. 기획의 문제 정의에서 **MCM에 남은 자산이 "Y2K·스트리트 감성 마니아층"** 으로 잡혔으니, 그 축이 분석에 없으면 인사이트가 안 나옵니다.

### 4-2. 30개 상품 크롤링 체크리스트

상품 1개당 아래를 채웁니다. 전시존 4개 × 상품 7~8개 배분을 권합니다.

- [ ] `name`, `price`, `external_url`(원본 상품 페이지), `images`(2~4장)
- [ ] `story` — 브랜드·디자인 스토리 2~3문장
- [ ] 8개 축 값 (위 목록에서만)
- [ ] `is_new` — 신상품 여부 (스코어링 10% 반영)
- [ ] `preset_answers` 3종 — **직접 작성**(LLM 생성 아님)
  - `price`: 가격 + 가격대 설명 · `material`: 소재·촉감·관리법 · `design_intent`: 디자이너 의도·시즌 컨셉
- [ ] `llm_context` — 챗봇용 자연어 설명 3~5문장 (⚠️ 응답에 안 나감)
- [ ] 이미지는 **다운로드해서 직접 서빙**하세요. 외부 핫링크는 데모 중에 깨질 수 있고, 브랜드 사이트가 referer를 막으면 전부 X표시가 됩니다

### 4-3. 16유형 4축 — 확정안

`type_code`는 4글자(명세 예시 `CLBM`과 형식 호환). 축별로 취향 벡터 점수를 계산해 부호로 결정 — **결정론적**입니다.

| 축 | 기호 | 판정 근거 |
| --- | --- | --- |
| 무드 | **C**lassic ↔ **T**rend | `mood`: classic_heritage·minimal ↔ y2k_street·bold_statement |
| 색 | **N**eutral ↔ **V**ivid | `color`: black·white·beige·navy ↔ red·pink·metallic·visetos_mix |
| 장식 | **P**lain ↔ **O**rnate | `pattern`: solid·logo_print ↔ visetos_monogram·studded |
| 용도 | **D**aily ↔ **S**pecial | `use_case`: daily·work ↔ travel·going_out |

예: `CNPD` = 클래식·무채·심플·데일리 → "절제된 무드를 즐기는 타입"

- [ ] 16개 유형의 `name` + `one_liner` 텍스트는 **기획에서 작성** (`analysis/character.py` 상수 테이블로 박음)

### 4-4. confidence 공식 — 확정안

"신호 총량 평가"만 있었으므로 아래로 확정합니다. 임의값이니 데모 데이터로 한 번 돌려보고 조정하세요.

```python
confidence = min(1.0,
    0.40 * min(1, products_viewed / 8)
  + 0.30 * min(1, dwell_total_ms / 240_000)     # 4분
  + 0.20 * min(1, questions / 3)
  + 0.10 * min(1, saves / 2)
)

CONFIDENCE_EXPLORING = 0.35   # 미만이면 "탐색 중" + 인접 유형 함께 제시
```

가장 약한 신호(단순 조회)에 가장 낮은 상한을 두고, 의도가 강한 행동(찜·질문)에 비중을 준 형태입니다.

### 4-5. 추천 개수
`REPORT_RECOMMENDATION_COUNT = 8` (히어로 1개 + 그리드 8개). 상품이 30개뿐이라 그 이상 노출하면 추천이 아니라 목록이 됩니다.

## 5. 작은 결정들

| 항목 | 결정 |
| --- | --- |
| `dwell_ms` 신뢰 | 서버에서 **상한 클램프 `DWELL_MAX_MS = 300_000`(5분)**. 탭을 백그라운드에 두면 30분이 찍히는데, 가장 중요한 신호를 검증 없이 믿으면 프로필이 망가집니다 |
| `store_enter`·`visit_start`·`visit_end` | **서버가 생성한다.** `/enter`에서 앞 2개, `/finish`에서 `visit_end`. 프론트는 이 3개를 보내지 않는다 (둘 다 보내면 퍼널 분모가 2배) |
| `GET /chat/messages` | **페이지네이션 없음**(타임라인은 전량 필요). 안전장치로 최근 200개 상한. 목록 페이지네이션 기본 적용 규칙의 명시적 예외 |
| 429 throttle | **`/chat`에만** 적용, `visit_token` 기준 분당 20회. LLM 비용 방어선이 유일한 목적이라 다른 엔드포인트엔 안 붙인다 |
| 이미지 서빙 | 크롤링 이미지를 다운로드 → `media/products/`, dev는 Django가 서빙. 30개면 용량 부담 없음 |
| 관리자 대시보드 우선순위 | **`/admin/funnel` + `/admin/products` 먼저.** `/scenes`·`/cohorts`·`/chat-insights`는 프론트 화면이 나올 때만 |
| SSE 배포 | ASGI(`uvicorn`) + 응답에 `X-Accel-Buffering: no`. 프록시가 버퍼링하면 스트리밍이 통째로 지연됩니다 |
| `.env` | `OPENAI_API_KEY`, `DJANGO_SECRET_KEY`, `DEBUG`, `DEFAULT_STORE_ID`, `ALLOWED_HOSTS`, `CORS_ALLOWED_ORIGINS` — 키 이름만 `.env.example`에 |
